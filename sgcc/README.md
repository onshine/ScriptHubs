# 网上国网签到（SGCC · 国家电网 95598）

网上国网 App 的**积分每日签到** Loon 插件。用手机号 + 密码自动登录并签到，**不需要抓包、不需要 MITM**。脚本本体已内置本仓库，不依赖上游实验分支。

```
https://raw.githubusercontent.com/onshine/ScriptHubs/main/sgcc/SGCC.plugin
```

> **R1.0.1 修了一个会导致插件不可用的 bug**：R1.0.0 的 `[Script]` 行写法有误，Loon 解析失败会把整条 `[Script]` 丢掉（插件详情页里看不到脚本行）。若你装的是 R1.0.0，请**删掉插件重新添加**。

## 目录内容（R1.0.1 起脚本已内置）

```
sgcc/
  ├── SGCC.plugin   # Loon 插件（本仓库）
  ├── sgcc.js       # 脚本本体（作者 MaYIHEI，已内置本仓库）
  └── README.md
```

**R1.0.0 曾是「纯外壳」（脚本引用上游 URL），R1.0.1 起改为内置脚本。** 原因：上游把方案放在 **`testing` 实验分支**上（默认分支 `main` 仍是旧的抓 Cookie 方案），而实验分支随时可能被删或改路径，引用式一旦断掉插件会**静默失效**（Loon 拉不到脚本，只表现为"什么都没发生"）。内置后上游怎么动都不影响你使用。

## 相比旧版（抓 Cookie）好在哪

你原来那份 `cron-cookie.lpx` 里的 sgcc 是**旧方案**（`main` 分支，2026-06-22），两者差别很大：

| | 旧版（抓 Cookie，你现在的） | 本插件（账密登录，新版） |
|---|---|---|
| 工作方式 | 抓 Cookie + 复用抓到的签到请求 | 手机号 + 密码自动登录签到 |
| 需要 MITM | ✅ 要解密 `csc-service.sgcc.com.cn` | ❌ **不要** |
| 需要手动触发 | ✅ 每次失效都要开 App 进签到页重抓 | ❌ 只有**首次**要填一次短信验证码 |
| 凭据有效期 | Cookie ≥4.5 天，失效就得重抓 | 服务端 token **15 天**，到期自动重登 |
| 能知道签到结果吗 | ❌ 只知道"有响应" | ✅ 能读到「今日签到完成 / 已签到 / 获得 X 签到金」 |
| 失败原因 | ❌ 服务器失败统一回「系统正忙」，只能猜 Cookie 失效 | ✅ 有明确错误码 |
| 脚本体积 | 18 KB | 54 KB（多了国密协议栈） |

## 安装

1. Loon →「配置」→「插件」→ 右上角 `+` → 粘贴上面的插件地址
2. 打开插件设置，填：
   - **手机号**：网上国网登录手机号（没设过密码的，先在 App 里设一下）
   - **密码**：网上国网登录密码
   - **签到时间**：默认 `30 8 * * *`（每天 8:30），可自行修改
3. **手动运行一次**：在插件详情页往下拉到 `[Script]` 那一节，点「网上国网签到」那一行末尾的 **▷** 按钮
   - Loon **没有**独立的"运行"菜单，手动运行就是这个 `[Script]` 行上的 ▷
4. 如果通知提示「首次登录需短信验证」：
   - 把收到的 **6 位验证码**填到插件设置的「**短信验证码**」
   - **15 分钟内**再点一次 ▷ 手动运行
   - 登录成功后脚本会**自动清空**这个字段
5. 之后就交给 cron，每天自动签到，不用再管

> ⚠️ **如果插件详情页里看不到 `[Script]` 那一节**，说明插件解析失败（R1.0.0 曾因语法错误导致整条 `[Script]` 被 Loon 丢弃）。请删掉插件重新添加 R1.0.1 或更高版本。

## 配置项

| 参数 | 默认值 | 说明 |
|---|---|---|
| `phone` | 空 | 登录手机号，留空则读 BoxJS |
| `password` | 空 | 登录密码，留空则读 BoxJS。⚠️ 见下方「密码锁定」 |
| `sms` | 空 | 仅首次登录用，成功后自动清空 |
| `cron` | `30 8 * * *` | 签到时间（分 时 日 月 周） |
| `debug` | 关 | 打开后 Loon 日志会打印服务器返回，排查用 |

这 5 项会以 `{${phone}, ${password}, ${sms}, ${debug}}` 的形式传给脚本（与脚本头部声明的 `argument=[{phone},{password},{sms},{debug}]` 一一对应）。

## ⚠️ 风险提示（请务必看完）

**1. 本插件需要把你的手机号和密码存在本机**
密码保存在 Loon 插件设置（或 BoxJS）里。**不要**分享含账号密码的插件配置或 BoxJS 备份。

**2. 密码连续输错 5 次会锁定 30 分钟**
填错的时候先把密码改对**再**运行，**不要反复重试**。这是上游 README 明确写的。

**3. 是否影响手机 App 的登录状态，作者说"待观察"**
脚本是按 App 的方式登录的（同一后端、同一套登录接口）。理论上会新增一个"登录设备"，但**会不会把你的 App 挤下线，作者自己也没验证过**。介意的话先别用，或者做之前记一下 App 里是否还能正常用。

**4. 上游在实验分支，随时可能变更** —— 见顶部说明。

## 常见问题

**Q：为什么这个插件没有 `[MITM]` 段？**
因为新版走账密登录，请求由脚本自己发出（cron 任务），不需要拦截/解密 App 流量。这是设计如此，不是配置漏了 —— `loon-spec-check.py` 会为此报一条 WARN，可以忽略。

**Q：为什么不直接用上游 URL 引用（像 `pingme/`、`wetalk/` 那样）？**
本仓库默认确实遵循「引用而非复制」，但这次**刻意改成内置**，原因就是上面说的：
上游把方案放在 `testing` 实验分支，引用式一旦遇到上游删库/改路径，插件会**静默失效**，
表现是"什么都没发生"，极难排查。已实测踩到过这个类别的坑，所以选择内置换稳定。
（`pingme/`、`wetalk/` 引用的都是作者 **`main` 主干**上的稳定文件，风险性质不同。）

**Q：内置了脚本，怎么跟进上游更新？**
需要我手动同步。脚本自带版本号（`[INFO] 脚本版本 2026-10-15.r1`），
在 Loon 日志里能看到当前跑的是哪版。上游有实质更新时告诉我，我拉新的快照上来。

**Q：怎么切换回旧版（抓 Cookie）？**
你原来的 `cron-cookie.lpx` 里那份 sgcc 我**完全没有动**（`cron-cookie.lpx` 的 `sgcc` 开关仍是 `switch,false`）。两个插件互不干扰，想用哪个开哪个。新版跑通之前，旧版可以继续留着兜底。

**Q：提示「缺账号密码」？**
插件设置里手机号或密码是空的，填上再运行。

**Q：一直提示「登录/签到异常」？**
先打开「调试模式」，看 Loon 日志里 `[DEBUG]` 那行的实际返回。若是 `11401`（网络连接超时）多是偶发，重试即可；反复失败请确认账号密码正确（注意别触发 5 次锁定）。

### 协议实现已实测可通（R1.0.0/R1.0.1 验证记录）

2026-10-15 在 iSH 里搭 Node 模拟 Loon 环境（`$httpClient`/`$persistentStore`/`$argument` 全 mock，用 `new Function` 隔离 `module.exports` 强制走 Loon 分支）实测：

```
[INFO] 脚本版本 2026-10-15.r1
[DEBUG] emss-uia-center-front/member/c2/f01 => {"code":"11401","data":{},"message":"网络连接超时(RK001),请重试!"}
```

`code 11401` 是**业务层**错误码（因为用的是假账号），**不是协议错误** —— 说明脚本的
SM4 信封加密 + SM2 密钥交换 + SM3 签名、Turing 设备令牌（`deviceToken`/`AppGuid`）、
登录参数 `checkCode` 全部被服务器正常接受并解密。连跑 3 次响应一致。

**结论：协议实现是通的**，作者标「待验证」应是缺真机账号跑完整流程（短信验证 + 实际签到），而非代码不可用。但这**不能替代你自己用真账号跑一遍**。
