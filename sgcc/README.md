# 网上国网签到（SGCC · 国家电网 95598）

## R10（2026-11-03）：受控自动恢复，解决「开过 App 就长期失败」

### 问题是什么

签到会话会被**官方 App 的登录挤掉**。被挤掉后，签到接口返回的不是 `-200/-201`，而是 `RK001`。旧版 R9 把所有 RK001 当成风控，**直接停 30 分钟且永不重登**，于是本地还显示「剩 12 天」，实际每天都是同一个 RK001。

这正好解释了你的情况：你为了领 8/15/21/28 天奖励会开 App 登录一次，**每开一次就可能挤掉脚本会话**，之后脚本就废了，直到手动恢复。

实测证据（2026-11-03）：会话被服务端拒绝（余额接口 `-201`）→ 保留原设备重建会话 → **同样的签到请求立刻返回 `102007 今日已参与`，余额查询返回 1485**。说明设备身份没问题，问题在会话。

### 改了什么

| | R9 | R10 |
|---|---|---|
| 签到回 RK001 | 一律当风控，停 30 分钟，不重登 | **若本次复用了旧会话 → 重登一次再签到** |
| 重登频率 | — | **每天最多一次**（`sgcc_recover_day`），避免反复把 App 挤下线 |
| 重登后仍失败 | — | 停手、写冷却、明确提示「问题不在会话」 |
| 刚登录就失败 | 停 | **不重登**（重登无意义） |
| 短信保护 | 15 分钟/每日 3 条 | 不变 |
| 开关 | — | 插件新增「会话被挤掉时自动恢复」，**默认开** |

首次上线即命中真实复发场景，自动恢复按预期生效：

这一条同时证明了三件事：① 旧会话确实已被服务端判废（`RK001` 就是它，不是风控）；② 设备身份没问题——重登后**同一套模拟设备**签到直接成功；③ R10「每天一次受控恢复」足够应付日常被挤掉的频率。

### 什么时候仍然会失败

- 设备身份被判定异常（重登后仍 RK001）→ 提示会明确说，不要继续重登。
- 当天已经自动恢复过一次 → 当天不再重登。
- 需要短信验证（4006）→ 按提示填验证码后再运行。

## 会话恢复：R1.0.0（2026-11-03）

**只在单次验证返回 `explicit_session_rejection`（如 `-201`）之后使用。** 它保留原设备 seed 和缓存设备令牌，只重新建立登录会话；**不签到、不生成新设备、不循环重登**。

```text
https://raw.githubusercontent.com/onshine/ScriptHubs/main/sgcc/SGCC_SessionRecover.plugin
```

### 使用步骤

1. 添加上述插件，在它的设置里填**手机号**和**密码**（与现有会话同一账号；只填在这个诊断插件里，**不要发到聊天**）。
2. 手动运行「网上国网会话恢复」一次。
3. 若返回 `sms_required`：把收到的 6 位验证码填进本插件的「短信验证码」，**再运行一次**。验证码不填进聊天。
4. 若返回 `session_rebuilt`：会话已重建。**本入口不会替你签到**；按需等原签到任务的下一次运行。
5. 若返回 `login_risk_control`、`sms_verification_failed` 或其它 `stopped`：停下，不要连续点击。

### 硬性限制

- 每次手动运行**最多 2 次请求**（1 次登录 + 最多 1 次发短信）；任何失败都不重试。
- **短信一天最多 1 条**，且只在服务器返回 4006（新设备验证）时才会发送。
- **绝不写 `sgcc_device`**，绝不打开 `sgcc_clear`；设备 seed 与缓存令牌原样复用。
- 只有登录成功后才会覆盖 `sgcc_session`；失败不会破坏现有会话。
- 以下情况会**零请求停止**：原签到脚本的本地冷却仍在生效、设备缓存超过 4 小时或时间不一致、seed 非法、手机号与现有会话账号不一致、没有可核对的旧会话且未手动打开「强制重建」。
- 输出不含手机号全文、密码、验证码、token、seed、设备令牌或异常原文。
- 密码连续输错 5 次会锁定 30 分钟；填错先改对再运行。

### 结果含义

| result | 意义 |
|---|---|
| `session_rebuilt` | 已用原设备身份重建会话。**不保证**签到接口不再返回 RK001 |
| `sms_required` | 已发送一条验证码；填码后需要再运行一次 |
| `login_risk_control` | 登录被返回 RK 风控/校验码；已停止，不会重试或再发短信 |
| `sms_verification_failed` | 验证码未被接受；本次停止 |
| `sms_daily_limit` | 今天已通过本入口发过验证码，不再发送 |
| `stopped` | 本地门禁或协议校验未通过，见安全的 `stopReason`；仍不重试 |

脚本、插件和本段版本均为 **R1.0.0**。离线 mock 测试覆盖门禁、单次预算、短信节流、验证码分支、失败不覆盖会话与输出脱敏；**离线测试不等于真实登录成功**。

- 只复制原脚本中需要的加密/编码函数，按原规则从 seed 派生稳定 AppGuid；响应密钥增加曲线及完整性校验。原 `sgcc.js` 不变。
- 每次执行至多一笔请求；因为不写存储，**不是跨次限流器**，请不要反复手动运行。任何失败都不会自动重试或重登。

### 结果怎样理解

| result | 意义 |
|---|---|
| `accepted_for_balance_query` | HTTP正常、解密后的业务响应成功且余额格式有效。本次余额查询成功，降低全局会话失效嫌疑；**不证明签到风控通过** |

| `http_status_unconfirmed` | HTTP状态异常或缺失；不标完整成功 |
| `network_or_tls_error` / `network_timeout` | 没拿到可判断的响应；不能由此认定凭证过期 |

## 本地体检：诊断版 R1.0.1（2026-11-03）

这是独立的**手动诊断插件**，不替换原签到插件、不修改现有 `sgcc.js`，没有定时任务。

```text
https://raw.githubusercontent.com/onshine/ScriptHubs/main/sgcc/SGCC_Diagnostic.plugin
```

### 怎么用

1. 在 Loon 插件列表添加上述地址，名称为「网上国网本地体检」。
2. **不用填任何账号、密码或短信验证码**。体检直接读取 Loon 已保存的 `sgcc_session`、`sgcc_device`、`sgcc_data` 和本地冷却状态。
3. 找到「网上国网本地体检」的 Generic 脚本条目，手动运行一次。这是诊断条目，不是原来的「网上国网签到」。
4. 查看返回的 JSON 结果，或者该次运行日志；可以将**此诊断结果**复制给 Minis 分析。不要发送 BoxJS 备份、原始 token、设备 seed、完整设备令牌或密码。

### 检查范围与边界

- 不发 HTTP 请求、不登录、不发短信、不修改或清空任何存储。
- 首次下载插件和代码需要联网，但下载不会携带国网凭据；脚本执行本身只做本地读取。
- 输出只包含记录是否存在、用户ID是否非零、设备时间是否一致、相对有效期/年龄，以及比较结果；不输出凭据原文。
- `session.serverValidity` 明确为 `UNKNOWN`：这个工具**不能确认服务器仍认可 token**，也不能确认通过国网风控。
- `store_unavailable` 表示没有 Loon 存储接口；`check_incomplete` 表示读取或解析中断，不能把这两种状态解释成账号没登录。
- `capturedApp.sameTokenAsScript=false` 可以是不同客户端各自持有 token，单独不作为异常；某些账号省份为空也不能单独判错。
- Minis 的终端不能读取 Loon 的本地存储。这里的离线测试不是你的真账号检查；真实体检需在 Loon 执行。

版本：脚本头、`SCRIPT_VERSION`、插件说明均为 **R1.0.1**。离线测试涵盖空存储、有效本地期限、错误用户ID/设备时间、损坏JSON，以及无 Loon 接口/读取失败；不使用真实账号。

### 对历史说明的更正

以下旧说明中的部分判断过于肯定，以本段为准：

- 能解密 `11401/RK001` 响应，**不代表**设备令牌、认证或风控已通过。
- RK001 可能涉及旧会话失效或安全校验，不能仅凭此认定 IP 被封；本地“剩12天”不能证明服务器仍认可。
- R9 的30分钟是本地退避，不是服务端解封承诺，也没有30分钟后自动执行的计时器；R9 会阻止 RK001 自动重登。
- Loon 请求的 `node:"DIRECT"` 是合法的指定选路，不应说更高分流规则能覆盖它；但家庭网关可能另行透明代理。
- `sgcc_clear` 会清设备身份，排查时不要盲目开启；短信验证码也不要反复发送。

## 安装

1. Loon →「配置」→「插件」→ 右上角 `+` → 粘贴上面的插件地址
2. 打开插件设置，填：
   - **手机号**：网上国网登录手机号（没设过密码的，先在 App 里设一下）
   - **密码**：网上国网登录密码
   - **签到时间**：默认 `30 8 * * *`（每天 8:30），可自行修改
3. **手动运行一次**：在插件详情页往下拉到 `[Script]` 那一节，点「网上国网签到」那一行末尾的 **▷** 按钮
   - Loon **没有**独立的"运行"菜单，手动运行就是这个 `[Script]` 行上的 ▷
4. 如果通知提示「首次登录需短信验证」：
   - 把收到的 **6 位验证码**填到插件设置的「**短信验证码**」
   - **15 分钟内**再点一次 ▷ 手动运行
   - 登录成功后脚本会**自动清空**这个字段
5. 之后就交给 cron，每天自动签到，不用再管

> ⚠️ **如果插件详情页里看不到 `[Script]` 那一节**，说明插件解析失败被 Loon 丢弃了整个模块。
> 官方语义：`[Argument]` 或 `[Script]` 存在**任一非法项** → 整个模块不发布任何动作
> （现象正是「设置项都在、脚本一条不剩」）。R1.0.0/R1.0.1 都踩了这个坑，R1.0.2 已修。
> 请删掉插件重新添加 **R1.0.2 或更高版本**。

## ⚠️ 风险提示（请务必看完）

**1. 本插件需要把你的手机号和密码存在本机**
密码保存在 Loon 插件设置（或 BoxJS）里。**不要**分享含账号密码的插件配置或 BoxJS 备份。

**2. 密码连续输错 5 次会锁定 30 分钟**
填错的时候先把密码改对**再**运行，**不要反复重试**。这是上游 README 明确写的。

**3. 是否影响手机 App 的登录状态，作者说"待观察"**
脚本是按 App 的方式登录的（同一后端、同一套登录接口）。理论上会新增一个"登录设备"，但**会不会把你的 App 挤下线，作者自己也没验证过**。介意的话先别用，或者做之前记一下 App 里是否还能正常用。

**4. 上游在实验分支，随时可能变更** —— 见顶部说明。

## 常见问题

**Q：为什么这个插件没有 `[MITM]` 段？**
因为新版走账密登录，请求由脚本自己发出（cron 任务），不需要拦截/解密 App 流量。这是设计如此，不是配置漏了 —— `loon-spec-check.py` 会为此报一条 WARN，可以忽略。

**Q：为什么不直接用上游 URL 引用（像 `pingme/`、`wetalk/` 那样）？**
本仓库默认确实遵循「引用而非复制」，但这次**刻意改成内置**，原因就是上面说的：
上游把方案放在 `testing` 实验分支，引用式一旦遇到上游删库/改路径，插件会**静默失效**，
表现是"什么都没发生"，极难排查。已实测踩到过这个类别的坑，所以选择内置换稳定。
（`pingme/`、`wetalk/` 引用的都是作者 **`main` 主干**上的稳定文件，风险性质不同。）

**Q：内置了脚本，怎么跟进上游更新？**
需要我手动同步。脚本自带版本号（`[INFO] 脚本版本 2026-10-15.r1`），
在 Loon 日志里能看到当前跑的是哪版。上游有实质更新时告诉我，我拉新的快照上来。

**Q：怎么切换回旧版（抓 Cookie）？**
你原来的 `cron-cookie.lpx` 里那份 sgcc 我**完全没有动**（`cron-cookie.lpx` 的 `sgcc` 开关仍是 `switch,false`）。两个插件互不干扰，想用哪个开哪个。新版跑通之前，旧版可以继续留着兜底。

**Q：提示「缺账号密码」？**
插件设置里手机号或密码是空的，填上再运行。

**Q：一直提示「登录/签到异常」？**
先打开「调试模式」，看 Loon 日志里 `[DEBUG]` 那行的实际返回。若是 `11401`（网络连接超时）多是偶发，重试即可；反复失败请确认账号密码正确（注意别触发 5 次锁定）。
