# 车来了 每日签到（Loon）

自动完成车来了 App「**7天连续签**」活动的每日签到，并把奖励结果推送给你。

- 插件：`CheLaiLe_Checkin.plugin`
- 脚本：`chelaile-checkin.js`
- 版本：**R1.0.6**
- 适配：车来了 iOS 7.6.3 ｜ Loon ≥ 3.5.1

---

## 一、原理（基于真实抓包逆向，含在线验证）

车来的签到是 H5 活动页，挂在 `web.chelaile.net.cn` 下：

```
H5 页面   https://web.chelaile.net.cn/app-relate/everyday-sign/index.html
活动配置  GET /api/op-activity-api/daily-act/config
每日签到  GET /api/op-activity-api/daily-act/signin
```

**实测得到的五条结论**（2026-10-11，HAR 逆向 + 逐条在线验证）：

| # | 结论 | 验证方式 |
|---|---|---|
| 1 | **凭证只需 `udid` + `accountId` 两个参数** | 5 个参数排列组合穷举 31 种，只有含这两个的组合能返回本人数据 |
| 2 | **`secret` / `cityId` / `s` 可以完全省略** | 去掉后返回数据与完整参数逐字节一致 |
| 3 | **Cookie 完全不需要** | 不带任何 Cookie 同样返回 200 正常数据 |
| 4 | **`sign` / `signature` / `nonce` / `h5TimeStamp` 是装饰性的** | 伪造签名、甚至完全不带，均返回 200 |
| 5 | 请求头里**必须有 `Referer`**（值不校验） | 缺失 → 400；填成首页地址 → 仍然 200 |

> ⚠️ 第 1 条有个坑值得单独说：**只带 `udid` 也能通过 HTTP 校验**，但返回的是**匿名数据**
> （`signRewards[0].status = "unsigned"`、`activityId` 变成 `"1"`）。必须同时带 `accountId`
> 才能拿到本人账户状态。所以判断"接口通不通"不能只看状态码，**要看数据是不是自己的**。

## 二、安装

Loon → 配置 → 插件 → `+`，填插件地址：

```
https://raw.githubusercontent.com/onshine/ScriptHubs/main/chelaile-checkin/CheLaiLe_Checkin.plugin
```

装好后**打开车来了 App → 进入「每日签到」页**（进页面就行，不必手动点签到）。
抓取成功时 Loon 会**弹一条通知**「✅ 已获取签到凭证」，之后就再也不用管了。

> 没等到通知？先看第四节「抓不到凭证怎么办」。

## 三、配置项

| 参数 | 默认 | 说明 |
|---|---|---|
| `cron` | `5 8 * * *` | 每日执行时间，默认 08:05 |
| `udid` | 空 | 一般留空，用抓包自动捕获的值。手动填写时为 40 位十六进制 |
| `accountId` | 空 | 一般留空，用抓包自动捕获的值。手动填写时为数字 |
| `notify_on_capture` | **开** | 抓到凭证时推送一次通知（同一凭证只提示一次） |
| `notify_when_signed` | **开** | 当天已签到时也推送通知；关掉后只在签到有动作或出错时通知 |
| `debug` | 关 | 输出接口原始响应，排查时打开 |

## 四、抓不到凭证怎么办（常见问题）

抓凭证靠 `http-request` 钩子，**前提是 Loon 能解开车来了的 HTTPS**。

**先做一次二分判断**（`debug` 打开时有效，默认已开）：

| 现象 | 结论 | 该修什么 |
|---|---|---|
| 弹「✅ 钩子已触发」 | MITM 正常，钩子能拦到请求 | 问题在凭证解析 → 第 3、4 步 |
| 弹「⚠️ 抓到请求但缺 accountId」 | MITM 正常 | 重新进一次「每日签到」页 |
| 弹「✅ 已获取签到凭证」 | 全好了 | 无需操作，等每天自动签到 |
| **什么都不弹** | 钩子根本没被触发 | MITM 或证书问题 → 第 1、2 步 |

按顺序排查：

1. **Loon 的 MITM 开关是否已打开**
   Loon → 配置 →（对应配置）→ `MitM` 里能看到 `web.chelaile.net.cn`（插件会自动 `%APPEND%`）。
2. **证书是否已安装并信任**
   只装描述文件**不算**，必须再去 iOS「设置 → 通用 → 关于本机 → 证书信任设置」把 Loon 的根证书**打开**。
   （少这一步，钩子完全不会触发，表现为"毫无反应"）
3. **确实进了「每日签到」页**
   只是打开 App 首页不一定发这些请求。签到页的接口是 `daily-act/config`，
   抓包里它出现在你**打开签到页**的那一刻。
4. **看运行日志**
   Loon → 工具/日志 → 找到 tag 为 `车来了-抓凭证` 的脚本，成功会打印
   `已捕获凭证 udid=xxxxxx***len=40 accountId=xxxxx`。
5. 仍然不行 → 手动兜底：在 Argument 里填 `udid` 和 `accountId` 两个值
   （`udid` 是 40 位十六进制，`accountId` 是数字）。填好后**签到本身不需要 MITM**，
   只有"自动抓凭证"这一步需要。

> 说明：R1.0.1 及更早版本抓成功时**只写运行日志、不发通知**，容易让人以为没生效——
> R1.0.2 起会在抓到凭证时弹通知，并在"命中请求但缺 accountId"时也提示一次。

## 五、FAQ

**Q：为什么不需要 Cookie，也不需要那些签名参数？**
实测结论：这些端点的鉴权只看 `udid` + `accountId`，Cookie 与 `sign/signature/nonce`
服务端不校验（详见第一节表格）。所以本插件**不需要 `requires-body`**，
抓包钩子只读 URL 就够，开销极小。

**Q：改了插件的 Argument 之后，Loon 里脚本条目消失了？**
`[Argument]` 里**不要用 `input,"默认值"` 写法**——实测会导致 Loon 解析不出整个 `[Script]` 段
（表现为插件装上后没有任何条目、脚本完全不执行）。用**纯文本值**（如 `cron = 5 8 * * *`）
或 `switch,true/false` 都是正常的。

**Q：签到失败怎么办？**
打开 `debug` 开关跑一次，看运行日志里的 `config 原始响应` / `signin 原始响应`。常见情况：
- `status=1002` + `今日已签到` → 已经签过了，属正常
- `status=400` + `Missing Request Parameter: udid` → 凭证丢了，重新抓一次
- `status=0002` + `非法请求` → 凭证不对（多半是 `accountId` 填错或缺失）
- 活动下线/换期 → 报 `读取活动配置失败`，等新一期活动上线

**Q：打开车来了 App，为什么没有收到通知？**
通知刻意做成**不刷屏**：
- **凭证有变化**（首次抓到 / 换了账号）→ 提示一次「✅ 已获取签到凭证」
- 其余情况**每天首次**打开签到页 → 提示一次「✅ 凭证正常」
- 同一天内重复打开 → 不再提示

所以「没有提示」通常意味着凭证早就抓好了、一切正常。想确认可以：
把 `debug` 打开看运行日志，或手动跑一次 cron——日志里会显示 `凭证来源: 抓包存储`。

**Q：会不会误签 / 重复签？**
不会。脚本先用 `config` 判断 `signRewards[].signDate == 今天`，
已签就直接跳过，连 `signin` 都不发。

## 六、已知边界

- **判断"今天是否已签"必须用 `signDate`，不能用 `status`。**
  `status == "signed"` 表示"本周期内该天已签"，昨天签的第 1 天，今天看仍是 `signed`。
  只看 `status` 会导致**第二天开始每天都跳过签到**。
- 本插件只做**签到**。活动里的「惊喜任务」（`taskType: share` 分享至朋友圈、
  `taskType: video` 看视频）**没有实现**——那两个接口需要伪造"已完成"状态去领奖励，
  与签到（点一下按钮就完成）性质不同，本脚本不做。
- 若车来修改活动接口路径或鉴权规则，需要重新抓包核对（脚本会把原始响应打在 `debug` 日志里）。
