# 车来了 每日签到（Loon）

自动完成车来了 App「**7天连续签**」活动的每日签到，并把奖励结果推送给你。

- 插件：`CheLaiLe_Checkin.plugin`
- 脚本：`chelaile-checkin.js`
- 版本：**R1.0.8**
- 适配：车来了 iOS 7.6.3 ｜ Loon ≥ 3.5.1

---

## 一、原理（基于真实抓包逆向，含在线验证）

车来的签到是 H5 活动页，挂在 `web.chelaile.net.cn` 下：

```
H5 页面   https://web.chelaile.net.cn/app-relate/everyday-sign/index.html
活动配置  GET /api/op-activity-api/daily-act/config
每日签到  GET /api/op-activity-api/daily-act/signin
```

### ★★ 读接口和写接口的鉴权不一样（这是最容易踩的坑）

| 接口 | 必需参数 | 少了会怎样 |
|---|---|---|
| `config`（读） | `udid` + `accountId` | 只有 `udid` 会拿到**匿名数据**（`signRewards[0].status="unsigned"`、`activityId="1"`） |
| `signin`（写） | `udid` + `accountId` + **`secret`** + **`s`** | `0002 非法请求`；补了 `secret` 还缺 `s` → `400 Missing Request Parameter: s` |

**`0002 非法请求` 的真实含义是「缺 secret」，不是「凭证伪造」** —— 我最初把它误判成后者，
白绕了很久。实测三种组合：

```
udid + accountId                  → 0002 非法请求
udid + accountId + secret         → 400 Missing Request Parameter: s
udid + accountId + secret + s=1   → 00 签到成功   ✅
```

`s` 只要**非空**即可（实测填 `1` 就能签到成功），所以脚本给它默认值 `1`。

### 其它四条实测结论

| # | 结论 | 验证方式 |
|---|---|---|
| 1 | **Cookie 完全不需要** | 不带任何 Cookie 同样返回 200 正常数据 |
| 2 | **`signature` / `nonce` / `h5TimeStamp` 服务端并不校验** | 伪造签名、甚至完全不带，均返回 200 |
| 3 | 请求头里**必须有 `Referer`**（值不校验） | 缺失 → 400；填成首页地址 → 仍然 200 |
| 4 | `secret` **不需要**自己算，从 App 请求 URL 里就能抓到 | 见下方说明 |

> H5 页面里确实会调 `sdkCall("crypto", …)` 算一个 `signature`，但那是走
> **车来了 App 的原生桥**（`window.cll`）实现的，网页里没有 JS 兜底实现，
> 我们在脚本里复现不了 —— **好在服务端压根不校验它**，所以不影响自动化。

> 第 2 条那个「只带 `udid` 返回匿名数据」的坑值得记住：**判断接口通不通不能只看状态码，
> 要看数据是不是自己的。**

## 二、安装

Loon → 配置 → 插件 → `+`，填插件地址：

```
https://raw.githubusercontent.com/onshine/ScriptHubs/main/chelaile-checkin/CheLaiLe_Checkin.plugin
```

装好后**打开车来了 App → 进入「每日签到」页**（进页面就行，不必手动点签到）。
抓取成功时 Loon 会**弹一条通知**「✅ 已获取签到凭证」，之后就再也不用管了。

> 没等到通知？先看第四节「抓不到凭证怎么办」。

## 三、配置项

| 参数 | 默认 | 说明 |
|---|---|---|
| `cron` | `1 0 * * *` | **主任务**执行时间，默认**每天 00:01**（`分 时 日 月 周`，可自定义） |
| `cron_backup` | `5 8 * * *` | **补签兜底**执行时间，默认 08:05（可自定义，也可删掉对应那行来取消兜底） |
| `udid` | 空 | 一般留空，用抓包自动捕获的值。手动填写时为 40 位十六进制 |
| `accountId` | 空 | 一般留空，用抓包自动捕获的值。手动填写时为数字 |
| `secret` | 空 | **一般留空**，用抓包自动捕获的值（32 位十六进制）。签到接口必须带，**少了必返回 `0002 非法请求`**；抓不到时可手动粘贴 |
| `s` | `1` | 签到接口要求非空即可，默认 `1`，一般不用改 |
| `notify_on_capture` | **开** | 抓到凭证时推送一次通知（同一凭证只提示一次） |
| `notify_when_signed` | **开** | 当天已签到时也推送通知；关掉后只在签到有动作或出错时通知 |
| `debug` | 关 | 输出接口原始响应，排查时打开 |

## 四、抓不到凭证怎么办（常见问题）

抓凭证靠 `http-request` 钩子，**前提是 Loon 能解开车来了的 HTTPS**。

**先做一次二分判断**（`debug` 打开时有效，默认已开）：

| 现象 | 结论 | 该修什么 |
|---|---|---|
| 弹「✅ 钩子已触发」 | MITM 正常，钩子能拦到请求 | 问题在凭证解析 → 第 3、4 步 |
| 弹「⚠️ 抓到请求但缺 accountId」 | MITM 正常 | 重新进一次「每日签到」页 |
| 弹「✅ 已获取签到凭证」 | 全好了 | 无需操作，等每天自动签到 |
| **什么都不弹** | 钩子根本没被触发 | MITM 或证书问题 → 第 1、2 步 |

按顺序排查：

1. **Loon 的 MITM 开关是否已打开**
   Loon → 配置 →（对应配置）→ `MitM` 里能看到 `web.chelaile.net.cn`（插件会自动 `%APPEND%`）。
2. **证书是否已安装并信任**
   只装描述文件**不算**，必须再去 iOS「设置 → 通用 → 关于本机 → 证书信任设置」把 Loon 的根证书**打开**。
   （少这一步，钩子完全不会触发，表现为"毫无反应"）
3. **确实进了「每日签到」页**
   只是打开 App 首页不一定发这些请求。签到页的接口是 `daily-act/config`，
   抓包里它出现在你**打开签到页**的那一刻。
4. **看运行日志**
   Loon → 工具/日志 → 找到 tag 为 `车来了-抓凭证` 的脚本，成功会打印
   `已捕获凭证 udid=xxxxxx***len=40 accountId=xxxxx`。
5. 仍然不行 → 手动兜底：在 Argument 里填 `udid` 和 `accountId` 两个值
   （`udid` 是 40 位十六进制，`accountId` 是数字）。填好后**签到本身不需要 MITM**，
   只有"自动抓凭证"这一步需要。

> 说明：R1.0.1 及更早版本抓成功时**只写运行日志、不发通知**，容易让人以为没生效——
> R1.0.2 起会在抓到凭证时弹通知，并在"命中请求但缺 accountId"时也提示一次。

## 五、FAQ

**Q：为什么不需要 Cookie，也不需要那些签名参数？**
实测结论：这些端点的鉴权只看 `udid` + `accountId`，Cookie 与 `sign/signature/nonce`
服务端不校验（详见第一节表格）。所以本插件**不需要 `requires-body`**，
抓包钩子只读 URL 就够，开销极小。

**Q：改了插件的 Argument 之后，Loon 里脚本条目消失了？**
`[Argument]` 里**不要用 `input,"默认值"` 写法**——实测会导致 Loon 解析不出整个 `[Script]` 段
（表现为插件装上后没有任何条目、脚本完全不执行）。用**纯文本值**（如 `cron = 5 8 * * *`）
或 `switch,true/false` 都是正常的。

**Q：签到失败怎么办？**
打开 `debug` 开关跑一次，看运行日志里的 `config 原始响应` / `signin 原始响应`。常见情况：
- `status=1002` + `今日已签到` → 已经签过了，属正常
- `status=400` + `Missing Request Parameter: udid` → 凭证丢了，重新抓一次
- `status=0002` + `非法请求` → 凭证不对（多半是 `accountId` 填错或缺失）
- 活动下线/换期 → 报 `读取活动配置失败`，等新一期活动上线

**Q：打开车来了 App，为什么没有收到通知？**
通知刻意做成**不刷屏**：
- **凭证有变化**（首次抓到 / 换了账号）→ 提示一次「✅ 已获取签到凭证」
- 其余情况**每天首次**打开签到页 → 提示一次「✅ 凭证正常」
- 同一天内重复打开 → 不再提示

所以「没有提示」通常意味着凭证早就抓好了、一切正常。想确认可以：
把 `debug` 打开看运行日志，或手动跑一次 cron——日志里会显示 `凭证来源: 抓包存储`。

**Q：会不会误签 / 重复签？**
不会。脚本先用 `config` 判断 `signRewards[].signDate == 今天`，
已签就直接跳过，连 `signin` 都不发。

## ★ 定时任务（cron）不自动跑怎么办

这是**最容易误判**的一环：脚本本身没问题（手动一点就跑成功），但到点没动静。
Loon 的 cron 脚本**只在 Loon 处于运行状态时**才会触发，完全受 iOS 后台策略摆布：

1. **Loon 必须处于「已连接」状态**（VPN 开着）—— 从后台划掉 Loon，cron 就停了
2. **iOS 设置 → 通知 → Loon 必须允许通知**，否则跑成功了你也看不到，会误以为没跑
3. **低电量模式**会显著抑制后台唤醒
4. **Loon → 配置 →「脚本」开关**必须是打开的
5. 手机深度待机 / 长时间锁屏时，iOS 可能直接挂起 Loon

### 5 分钟自检法（先分清是「没触发」还是「时间点不对」）

把 `cron` 临时改成 `*/5 * * * *`（每 5 分钟），等 5 分钟：

| 结果 | 结论 |
|---|---|
| 收到通知 | cron 机制**正常**，之前只是时间点落在设备休眠期 |
| 完全没通知 | cron **根本没触发** → 属上面 1～5 条的环境问题 |

测完记得把 `cron` 改回 `1 0 * * *`。

### 关于那条 08:05 的「补签兜底」

插件里除了主任务（00:01），还挂了一条 **08:05 的兜底 cron**。原因：**00:01 设备往往处于深度待机，
iOS 最容易把 Loon 挂起**，而早上 8 点左右手机通常是活跃的，补跑成功率更高。

- 脚本是**幂等**的：已经签过就直接跳过，不会重复签、不会多领
- 兜底那条传了 `notify_when_signed=false`：**已签时完全静默**，只有真的补签成功或出错才通知你
- 时间同样可自定义：改 `cron_backup` 即可（**默认 `5 8 * * *`，不是写死的**）
- 不想要？把 `[Script]` 里 `tag=车来了补签兜底` 那一行删掉即可

### 想要 100% 可靠

Loon 的生命周期由 iOS 管，**做不到 100%**。真正稳的方案：

- **快捷指令**：自动化 → 每天 00:01 → 「获取 URL 内容」直接打签到接口，完全不依赖 Loon
- **自己的 VPS**：写个 cron + Python 脚本（最稳，本目录的接口结论可直接复用）

## ★ 通知弹不出来 / 日志显示成功但没收到推送

第一步是**看运行日志**。R1.0.8 起每次通知都会留痕，cron 开头也会打印通知环境：

```
[车来了签到] 脚本版本 R1.0.8  通知环境: $notification=object.post✅ $notify=undefined
[车来了签到] 已发送通知: ✅ 签到成功
```

| 日志表现 | 原因 | 处理 |
|---|---|---|
| `通知环境: $notification=object.post✅` + `已发送通知:` | **脚本侧正常**，问题在 iOS | 见下面 ①② |
| `⚠️ 无可用通知接口` | 宿主没暴露通知 API | 报 bug 给我 |
| `⚠️ 通知发送失败:` | 调用抛错 | 日志里会带原因 |

**iOS 侧两个坑：**

① **`设置 → 通知 → Loon` 必须允许通知**（横幅/声音），并且没被「专注模式」拦掉。

② **Loon 在前台时，iOS 默认不显示自家 App 的本地通知横幅。**
你「点着 Loon 界面的执行按钮」手动跑脚本时，Loon 就处于前台 —— 通知很可能被系统直接丢掉了，
**看起来像没发**。验证方法：**把 Loon 切到后台（或锁屏）再触发**，通知就会正常出现；
定时任务（cron）本来就是后台执行，所以不受这条影响。

> 也就是说：手动测试时「没弹通知」**不代表定时任务也不会弹**。判断脚本有没有真的发出通知，
> 以运行日志里的 `已发送通知:` 为准。

## 六、已知边界

- **判断"今天是否已签"必须用 `signDate`，不能用 `status`。**
  `status == "signed"` 表示"本周期内该天已签"，昨天签的第 1 天，今天看仍是 `signed`。
  只看 `status` 会导致**第二天开始每天都跳过签到**。
- 本插件只做**签到**。活动里的「惊喜任务」（`taskType: share` 分享至朋友圈、
  `taskType: video` 看视频）**没有实现**——那两个接口需要伪造"已完成"状态去领奖励，
  与签到（点一下按钮就完成）性质不同，本脚本不做。
- 若车来修改活动接口路径或鉴权规则，需要重新抓包核对（脚本会把原始响应打在 `debug` 日志里）。
